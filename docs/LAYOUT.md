# LAYOUT

The repo by folder. What each crate may import is `ALLOWED` in
`scripts/kb-plugins.ts`; how the pieces meet is ARCHITECTURE.md.
`bun run docs` holds this page to the tree: every crate has a bullet, every
plugin is named, every script is in the list.

## crates/

A Rust workspace, cut by dependency, not by platform.

- `topology`: address, neighbours, sector seams, address <-> position.
  Pure integer logic where possible. No GPU, no IO.
- `worldgen`: the generator. Deterministic; also built to WASM for the
  server. A world's shape is a source: plates over the seed, or a baked field.
- `protocol`: wire messages generated from `proto/`; `lib.rs` alone by hand.
- `scene`: the plain data a client hands a renderer. No GPU, no generator.
- `avatar`: VRM avatars and humanoid clips: parse, retarget, pose. No GPU, no IO.
- `voxel`: a volume's cells, gestures, sight, faces and footing. No sphere:
  it imports no `topology`.
- `vox`: a MagicaVoxel file as one grid, its palette and its faces. No sphere.
- `part`: a placed thing that is no cell: its pose in the flat frame of its
  seat, its shape, what a line and a body meet of it. No sphere.
- `seat`: how cells and parts are seated on a world, as client and server
  both hold it: plots, a volume's bounds by the ground, a gesture on the
  wire, the frame of a point and a part read back from the world.
- `render`: all of wgpu lives here.
- `ui-native`: the desktop panel, all of egui.
- `client`: controller, streaming, the cells, the host of plugins. No
  window, no DOM. The seam, input, assets and figure know no body;
  controller, collision and streaming know one `Body`. The generator, sky,
  sea and moon stay the planet's.
- `plugins-client`, `plugins-world`: the version's plugins for each host,
  generated by `bun run plugins`.
- `world`: what a plugin's world half stands on, their host, and the cells
  where the world is decided.
- `module`: the shell of `world`, the WASM file the server runs.
- `shell-desktop` (winit), `shell-web` (wasm-bindgen), later `shell-xr`.
- `bench`: a frame's cost in WASM (`scripts/bench.ts`).

## The other folders

- `plugins/`: one folder a plugin: `world/`, `client/`, `wire/`, `web/`
  (PLUGINS.md). Today: `chat`, `build`, `items`.
- `server/`: Go, the world server: one binary is an instance. Its rules:
  `server/AGENTS.md`.
- `apps/web/`: Svelte + Bun, the web front end; hosts the WASM client. Its
  rules: `apps/web/AGENTS.md`.
- `proto/`: the core's schemas, the wire and the module's bridge, single
  source for Rust and Go; a plugin's is in its folder. `bun run proto`
  generates from them.
- `assets/`: a version's default set and its `manifest.json`.
  `assets/fields/`: baked fields from `bun run field`, gitignored.
- `docs/`: the topic docs, with `decisions/`, `questions/` and `sketches/`.
- `refs/`: reference checkouts, read-only (REFS.md).
- `scripts/`: every repeated command. No tribal knowledge.

## Commands

Each is a file in `scripts/` or a line in `package.json`:
`bun run setup | dev | server | web | wasm | assets | field | desktop | shot | webshot | bench | proto | plugins | module | kb | wf | docs | check | build`.

- `setup`: once after clone; installs the commit-msg hook.
- `shot`: a headless render to PNG with a fixed clock and seed;
  `bun run shot --slice M` for what is behind the ground.
- `webshot`: the same in a browser, for a `render` change, since WebGPU
  rejects what Metal lets by.
- `bench`: a frame's cost in WASM; it fails when a budget is blown.
