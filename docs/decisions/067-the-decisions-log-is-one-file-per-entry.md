# 67. The decisions log is one file per entry, and the index is generated (decided)

Logged 2026-09-24.

The log had 66 entries in one file of 1,650 lines: close to what one read
returns, growing 30 lines an entry, and read whole by an LLM that wanted one
entry. The same afternoon two agents appended an entry each, both numbered
65, because a number is taken by reading the tail of a file nobody had
re-read.

**One file per entry, in `docs/decisions/`**, named by its number and its
title. An entry is written once and then touched only to strike its title
and name what retired it. Reading one decision is one small file, and its
history is `git log` on that file.

**`docs/DECISIONS.md` is the index**, generated by `bun run docs gen` from
the files: number, date, title, status. About seventy lines, cheap to load,
and the titles are already written as decision sentences, so the index reads
as the summary. `bun run docs` fails when the index is stale, when two files
claim a number, when a number is skipped, or when an entry says it retires
another whose title is not struck.

**The shape of an entry is the rule, not a line cap.** The first paragraph
is the decision in one breath and stands alone; then the why, then Rejected,
then Lives in. A reader who needs only the what stops after the breath. An
LLM given a line cap pads; given a shape it stops. The story of how a
decision was reached goes in the commit message; the entry says what a
newcomer needs so as not to undo it.

Rejected: one file with a generated index at the top, which still has to be
grepped whole and still lets two writers take one number; splitting by theme,
which breaks the numbers everything cites; consolidating the founding entries
into ARCHITECTURE as Plataforma ITS did, because the rejected alternatives are
the value and ARCHITECTURE is the one doc that carries no history.

**Lives in:** CLAUDE.md § Docs style; `docs/DECISIONS.md`; `scripts/docs.ts`.
