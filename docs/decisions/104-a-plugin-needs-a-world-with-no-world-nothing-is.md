# 104. A plugin needs a world: with no world, nothing is built (decided)

Logged 2026-10-04.

A plugin is on when a world says it is, and with no world none is on,
building among them. A person builds inside a founded world, and every
stroke is an op the server applies and keeps. The founding screen, and a
client with no link, walk, fly and look.

**Why.** Marlus: the world is created first. What is built is kept (96), and
a stroke with no world to keep it is a sketch lost when the page closes,
made with the same tool and looking the same as one that stays. One path for
a change (93) is also one authority: the server decides, and a client that
builds alone is a second one nobody checks.

**What it takes away.** A client with no world builds freely today, in
memory: on the founding screen, and in the desktop app, which opens no
socket yet. Both lose the tool when building becomes a plugin. The desktop
has it again when it opens the socket. To build with no internet, a world
runs alone on the same machine.

**What the cut leaves open.** The client half imports the world half (101),
and `world::Host` hosts a world half wherever it is put. An engine that hosts
its world halves itself, a room of one, is one more host, written when a
desktop or a headset asks for it.

**Rejected:** building left on as a sketch where there is no world, an op a
client applies to itself.
